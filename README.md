# AI Mentor

A cross-platform desktop app (Rust + `egui`) that mentors you through advanced tech topics using
Josh Kaufman's **The First 20 Hours**. Pick your stacks with checkboxes, and the **Claude CLI**
deconstructs each one into its highest-leverage subskills, sequences them into a day-by-day plan
that gets **harder every day**, and sets a weekly project it will then **review from your GitHub
repo**. Everything is stored in SQLite and stays editable while you study.

The app is built around one goal: take you from zero to a **hands-on, interview-ready** engineer —
with a built-in **Full-Stack Java Spring Boot Developer** roadmap as the flagship track.

---

## What it does

| Feature | Detail |
| --- | --- |
| **Subject selection** | 29 seeded stacks grouped by Backend / Database / Frontend / DevOps / Cloud / Foundations, plus custom subjects. Selection persists in SQLite. |
| **20-hour plans** | Claude deconstructs the skill, ranks subskills by payoff, and sequences them into `ceil(target_hours × 60 / minutes_per_day)` daily sessions grouped into 7-day weeks. |
| **Complexity ramp** | Every day carries a difficulty of 1–5 that **never decreases**. The app enforces this in code after parsing — it clamps to 1–5, stable-sorts by difficulty, then renumbers days and weeks. Later days list the earlier subskills they reuse ("Builds on"). |
| **Hands-on gate** | Every day has a concrete coding task. A day **cannot be marked `done`** until its "Task completed" checkbox is ticked; un-ticking it drops the day back to *in progress*. |
| **Editable content** | Day lessons are Markdown, rendered with `egui_commonmark`. Toggle **Edit** for a raw editor. Once you edit a day it is flagged `content_edited` and only an explicit **Regenerate** replaces it. |
| **Interview readiness** | Each day carries 2–4 interview questions with strong-answer key points, a reveal toggle, and a 0–5 confidence self-rating. |
| **Roadmaps** | Ordered tracks with per-subject progress and an overall bar. The preset **Full-Stack Java Spring Boot Developer** roadmap seeds on first run; subjects unlock in sequence. Create, reorder and delete your own. |
| **Spaced repetition** | SM-2. Cards seed from every day's interview questions and from quiz mistakes; the Reviews tab serves what's due and reschedules on a 0–5 grade. |
| **Recall quizzes** | Per-day and per-week multiple-choice quizzes generated by the CLI, taken and scored in-app. Wrong answers become review cards. |
| **Project verification** | Enter your GitHub URL and hit **Verify**: the app shallow-clones the repo, runs the CLI *inside the clone* to review the whole codebase against that week's subskills and acceptance criteria, then stores a verdict, 0–100 score, Markdown report and a filterable issue list. Every run is kept as history. |
| **Analytics** | Stat tiles (streaks, hours, days completed, avg quiz score, cards due, peak difficulty), a GitHub-style activity heatmap drawn as a custom egui widget, a weekly-minutes trend, and a per-subject progress table. |
| **In-app updates** | The app checks GitHub Releases on launch and offers a one-click **Download & install** that replaces the running executable in place. |
| **Theme** | A dark and a light theme built on a validated palette, switchable from the header; the choice persists. |

## Updating

AI Mentor updates itself. On launch it asks GitHub Releases whether a newer version
carries a build for your platform; if one does, an **Update to vX.Y.Z** button appears in
the header and a full entry (with release notes) under **Settings → Updates**. Installing
downloads that release's archive and replaces the running executable in place — the new
version starts on the next launch. Nothing is ever installed without a click.

- **Check now** and the **check on startup** toggle both live in Settings.
- The check is anonymous: no token, no account. It reads the public releases of
  `Amithkrishna29z/ai-mentor`.
- A failed check or download leaves the running app untouched and reports the error in the
  status bar.
- The updater matches assets by the platform slug in their name (`linux-x86_64` /
  `windows-x86_64`), which is what `release.yml` produces — the two must stay in step.

## Prerequisites

1. **Rust toolchain** — stable, via [rustup](https://rustup.rs). (Built and tested on 1.97.)
2. **Claude CLI** — installed and on `PATH` as `claude`. All plan, lesson, quiz and review content
   comes from it. If your binary lives elsewhere or is named differently, set its path in
   **Settings** (see [Pointing at a different CLI](#pointing-at-a-different-claude-binary)).
3. **git** — required only for weekly-project verification (the repo clone). Missing git degrades
   gracefully: you get an error in the status bar, nothing crashes.

No external SQLite is needed — `rusqlite` is built with the `bundled` feature, so SQLite is
compiled into the binary. No system GUI libraries are needed on Windows; on Linux you need the
usual X11/Wayland + GL development headers (see the CI workflow for the exact apt list).

## Build and run

### Linux

```bash
./scripts/build-linux.sh          # or: cargo build --release
./target/release/ai-mentor
```

### Windows

```powershell
.\scripts\build-windows.ps1       # or: cargo build --release
.\target\release\ai-mentor.exe
```

### Cross-compiling for Windows from Linux

```bash
rustup target add x86_64-pc-windows-gnu
sudo apt install mingw-w64
cargo build --release --target x86_64-pc-windows-gnu
```

### Tests

```bash
cargo test
```

Covers the SM-2 scheduler, the difficulty-ramp guarantee, JSON extraction from fenced/prose-wrapped
CLI output, and the day-count formula.

### CI

`.github/workflows/build.yml` runs a matrix over `ubuntu-latest` and `windows-latest`: release
build, tests, and both binaries uploaded as artifacts. It fires on pushes to `main`, on pull
requests, and on demand.

### Releases (CD)

`.github/workflows/release.yml` builds and tests on both platforms, then packages each one —
binary plus this README — into `ai-mentor-<tag>-linux-x86_64.tar.gz` and
`ai-mentor-<tag>-windows-x86_64.zip`, and attaches both to a GitHub release with generated notes.

Cut a release by pushing a version tag:

```bash
git tag v0.1.0
git push origin v0.1.0
```

Running the workflow manually (**Actions → release → Run workflow**) builds and uploads the same
archives as run artifacts but publishes nothing — the publish job is gated on a `v*` tag, so it is
safe as a dry run.

## Where your data lives

One SQLite file, `ai_mentor.db`, in the platform data directory resolved by the `directories`
crate (`ProjectDirs::from("dev", "AiMentor", "ai-mentor")`):

| OS | Path |
| --- | --- |
| Windows | `%APPDATA%\AiMentor\ai-mentor\data\ai_mentor.db` |
| Linux | `~/.local/share/ai-mentor/ai_mentor.db` |
| macOS | `~/Library/Application Support/dev.AiMentor.ai-mentor/ai_mentor.db` |

The exact path for your machine is shown in the **Settings** window. Tables are created on first
run; deleting the file resets everything.

## Pointing at a different Claude binary

The CLI is invoked as:

```
<claude_cli_path> <prompt_flag> "<prompt>" <extra_args>
```

which defaults to `claude -p "<prompt>" --output-format text`. All four parts are editable in
**Settings**, so a wrapper script, an absolute path (`C:\tools\claude.exe`), or different flags all
work. **Test Claude CLI** there does a one-word round trip so a bad path surfaces immediately
rather than halfway through a plan generation.

Every CLI call runs on a background thread and reports back through an `mpsc` channel, so the UI
never blocks; the status bar shows a spinner and the number of jobs in flight.

## How failures degrade

- **No Claude CLI / non-zero exit** — the error lands in the status bar. Day content can be written
  by hand in the editor; a plan can be pasted as JSON.
- **Unparseable plan JSON** — the call is retried once with a "return valid JSON only" reminder. If
  that also fails, the raw output is shown in an editable box with an **Import JSON** button so you
  can fix and salvage it.
- **No git / clone failure** — verification reports the error and stores nothing.
- **Review without a JSON verdict block** — the prose report is still saved and displayed; the
  verdict shows as `unknown`.
- **CLI can't read the clone** — verification falls back to pasting filtered source files into the
  prompt (skipping `.git`, `node_modules`, `target`, `build`, `dist`, lockfiles and binaries, capped
  at 180 KB).

## Decisions made where the spec left room

- **Crate versions.** The pinned versions in the brief were stale by the time of writing, so the
  project is on the current mutually compatible set: `eframe`/`egui` 0.36, `egui_commonmark` 0.25,
  `egui_plot` 0.37, `rusqlite` 0.40, `directories` 6, `thiserror` 2. egui 0.36 moved to the unified
  `egui::Panel` API and `eframe::App::ui`, which is what the code uses.
- **Subject categories live in code**, not in the schema — the brief fixed the `tech_stacks` table,
  which has no category column. `models::CATALOGUE` owns the grouping; custom subjects show under
  **Custom**.
- **`src/ui/study.rs` was added** beyond the listed files to hold the Study tab's subject dropdown,
  the Overview/Day/Weekly switcher and the plan-repair box, keeping the three view modules focused.
- **Roadmap unlocking is threshold-based**, default **80%** of a subject's days done, configurable
  in Settings. Everything after the first uncleared subject shows as locked, but nothing is
  actually blocked — you can always open any subject.
- **Objectives render as a read-only checklist.** The schema has no per-objective state, so ticking
  them would not survive a restart; the hands-on checkbox is the real completion gate.
- **Weeks are renumbered as strict 7-day blocks** after the ramp sort, and any week the model
  skipped gets a generated placeholder project so no week is left without one.
- **Plan length follows the model.** Prompts ask for `ceil(target_hours × 60 / minutes_per_day)`
  days, but a plan that comes back slightly longer or shorter is kept as-is rather than truncated —
  the 20-hour target is tracked through logged minutes, which is what the progress bar reads.
- **Quizzes are reused.** "Take quiz" opens the existing quiz for that day/week if one exists;
  "New quiz" always generates a fresh set.
- **Window size persists** (written at most every 3 seconds), along with the active tab, active
  roadmap, last-open subject and theme choice.
- **The repo is public** so the updater can read release assets without a token. That was a
  deliberate choice over keeping it private and asking every machine for a GitHub token.
- **Colours come from a validated reference palette**, not ad-hoc picks. Surfaces are the ones
  that palette was validated against (`#1a1a19` dark, `#fcfcfb` light), the heatmap uses a
  one-hue sequential blue ramp, difficulty 1-5 uses a one-hue *ordinal* ramp with the number
  always shown, and verdict/severity badges use the reserved status palette with their label
  beside them - so nothing is carried by colour alone.
- **Updates are opt-in per install.** The check runs on startup by default (toggleable) but
  installation always needs an explicit click.
